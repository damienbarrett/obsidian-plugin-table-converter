# Refactoring opportunities

These are follow-up opportunities identified while building and installing version 1.0.0. They are not changes to the installed plugin.

1. **Test the Obsidian file workflow** (`src/main.ts:24-76`, `tests/acceptance.test.mjs:325`). The acceptance tests cover the pure converter, but T24 and T25 only check a path helper. Extract the read, backup, modify, and error-note sequence behind a small vault interface and test backup failure, source write failure, stale error deletion, and repeated commands with a fake vault. This would protect the data-changing part of the plugin.
2. **Remove redundant parser passes and state** (`src/converter.ts:436-472`, `src/converter.ts:627-631`). `detectNestedTable` makes an initial fence scan whose result is discarded, then scans the same lines again. The `#` heading branch also assigns `AFTER_H1` in both arms. Remove these no-op paths and keep one fence-state pass.
3. **Reduce the table parse model** (`src/converter.ts:24-34`, `src/converter.ts:416-427`). `bodyRowsRaw` and `bodyRows` contain the same trimmed cells, and the parser carries multiple header and line fields through conversion. Retain only fields used by rendering and validation so it is clearer which values are raw and which are decoded.
4. **Centralize file names and vault writes** (`src/main.ts:80-119`, `src/converter.ts:40-61`). The plugin calculates backup and error paths with converter helpers but separately reconstructs their display names. Derive display names from those paths, and use a shared create-or-modify helper for backup and error notes. This would keep naming and overwrite behavior in one place.
5. **Clarify pipe escaping with targeted cases** (`src/converter.ts:170-229`). The table splitter decides whether a pipe is escaped by checking only the immediately preceding character. Markdown escaping depends on the parity of consecutive backslashes. Add cases for literal backslashes followed by pipes and `<br>` text before changing this logic; then use one shared escape/unescape rule for titles and cells.
6. **Make build outputs explicit** (`esbuild.config.mjs:6-20`, `scripts/build-tests.mjs:3-11`). Production uses a watch context followed by `process.exit`, while tests write a generated bundle into `tests/`. A one-shot production build and an ignored temporary test output would simplify the build lifecycle and keep generated files separate from test sources.
